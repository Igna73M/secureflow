A SMALL, EXPLICIT SECURITY GATE

From scanner output
to a decision your pipeline can use.

SecureFlow brings configured scanner checks into one consistent, fail-closed result — so your automation always knows what to do.

01

Scan supported source

Bandit checks Python. Semgrep and ESLint check JavaScript. The CLI selects .py, .js, .cjs, and .mjs files.

02

Normalize findings

Scanner-specific output maps to shared finding fields: severity, source location, rule ID, and a blocking flag — all in structured JSON.

03

Evaluate policy

Required checks and blocking findings feed a structured report with a distinct decision — PASS, FAIL, or ERROR — and matching CLI exit code.

04

Keep a scan record

The local API scans one uploaded file or stores a submitted report in SQLite. Accounts keep scan history private; submitted reports stay unverified.

FOUR STEPS · ONE ENFORCEABLE OUTCOME

A gate that knows
when it cannot decide.

  1. 01

    Scan source

    Run the configured checks for supported Python or JavaScript files in the target directory.

  2. 02

    Normalize findings

    Bring scanner results into a consistent structure with shared fields for severity and blocking status.

  3. 03

    Evaluate policy

    Require complete checks and assess blocking findings. Missing or failed checks are never silent passes.

  4. 04

    Decide promotion

    Permit promotion only when the overall result is PASS. Both FAIL and ERROR deny promotion.

TRANSPARENT BY DESIGN

An error is not a green light.

Missing checks, invalid results, and scanner errors produce ERROR. Both ERROR and FAIL deny promotion. A PASS means only that the configured checks completed without policy-blocking findings — it does not prove code is vulnerability-free or make this project production-ready.
